# Template — Feature Request

> **Use:** seed a new BRD page. Fill what you know; Business Analysis populates the rest. Only S01-seed + Notion properties are mandatory to reach `Ready`.

```markdown
Title: [BRD-<XX>-<nnn>] <feature name>

## Properties
- Project: <select>
- Priority: P0 | P1 | P2 | P3
- Ready: ☐ (tick when pickable)

## S01 · Problem Statement (seed)
<1–3 sentences: what hurts, who feels it, why now>

## Context (optional, feeds Analysis)
- Trigger: <what prompted this — user feedback, metric, roadmap>
- Links: <docs, competitors, prior BRDs, Figma>
- Known constraints: <deadlines, dependencies, tech limits>
- Explicit non-goals: <what this must NOT become>
- Success looks like: <first guess at S02, freeform>

## Attachments
<screenshots, briefs>
```

## Rules

- One request = one feature area. Two unrelated asks = two pages.
- Don't pre-fill S03 requirements unless you have real ones — half-guessed requirements anchor Analysis worse than an honest empty section.
- Solution ideas welcome under Context, labeled as ideas — Analysis extracts the need behind them.

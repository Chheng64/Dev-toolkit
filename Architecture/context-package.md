# AI Context Package

> **Module:** Architecture / Foundation (v1.3)
> **Status:** Stable
> **Purpose:** `context/` — small generated summaries a session reads at bootstrap for consistent AI behavior, without loading the full toolkit. **Generated, never hand-edited.** The manifest and toolkit stay authoritative; `context/` is a derived cache.

## 1. Location & Files

`context/` at project repo root, five files:

| File | Summarizes | Source of truth |
|------|-----------|-----------------|
| `design.md` | Design config: Figma refs (or prototype-only mode), component library, token source, icon/typography, DS state + where the DS lives | manifest `design.*` + DS docs |
| `stack.md` | Stack + resolved profile + the exact list of applicable Standards/ files + declared gaps | manifest `stack.*` + [stack-profiles](stack-profiles.md) |
| `integrations.md` | Last validation results per integration + per-stage degradation consequences of anything unavailable | manifest `integrations.*` + [../Workflows/integration-validation.md](../Workflows/integration-validation.md) |
| `conventions.md` | Naming/branch/commit/PR contracts resolved for this project + pointer to `project-overrides.md` entries | manifest `git.*` + [integration-map](integration-map.md) §3 + overrides |
| `model-routing.md` | Stage → model tier table + escalation triggers, resolved for this project's active stages (headless profiles drop design rows) | [../AI/model-routing.md](../AI/model-routing.md) + profile |

Every file header: `<!-- GENERATED by toolkit onboarding <date> · toolkit <version> · DO NOT EDIT — regenerate via project-onboarding/integration-validation -->`

## 2. Rules

1. **Derived only.** No fact lives *first* in `context/`. Hand-edits are overwritten at next regeneration — deviations belong in `project-overrides.md`, config changes in the manifest.
2. **Regeneration triggers:** onboarding (full), re-onboarding of any section (affected files), integration-validation run (`integrations.md`), toolkit pin bump (all — routing/standards summaries may change).
3. **Session bootstrap order** (per [../AI/CLAUDE-global.md](../AI/CLAUDE-global.md)): project `CLAUDE.md` → `context/` (fast orientation) → manifest when a config fact is needed → full toolkit module only when the stage requires its procedure. Context summaries never substitute for a stage's workflow file.
4. **Drift check:** each file records the manifest state it was generated from (toolkit version + date). Orchestrator treats `context/` older than the manifest's `last_validated` as stale → regenerate before relying on it.
5. Content is summary + pointer, never copied prose: a `stack.md` line reads `react rules → toolkit/Standards/react.md`, not a paste of the rules.

## 3. Anti-Patterns

- Editing `context/` to change behavior — it's a cache; change the source.
- Growing context files into documents — each stays under ~40 lines; if it wants more, the content belongs in the manifest, overrides, or toolkit.
- Sessions quoting `context/` as authority in disputes — manifest/toolkit win; context regenerates.
